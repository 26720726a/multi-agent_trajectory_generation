## A-1 — 단독 롤아웃은 자유롭지 않았다 (확인, 수정함)

### 무엇이 잘못됐나

S5-3′/3″ 의 단독 기준선은 `ss.phase[:] = PHASE_DONE` 으로 나머지 구성원을
"끄고" 그 자리에 남겨 두었다. 코드를 따라가 보면 `PHASE_DONE` 은 **에이전트를
장면에서 빼지 않는다**:

| 위치 | 완료 에이전트에 대한 동작 |
|---|---|
| `safety/vo.py:79` | 건너뛰지 않는다. `aij = 1.0` — 회피 책임을 **전부** 산 에이전트가 진다 |
| `safety/project.py:42,49` | 쌍별 안전 투영의 대상으로 남는다. 다만 비킬 수 없으므로 살아 있는 쪽만 감속한다 |
| `planning/control.py:580` | 스스로 움직이지 않는다 — 제자리에 영원히 서 있다 |

즉 얼려 둔 이웃은 **정확히 가장 방해되는 곳(3 m 이내)에 놓인 움직이지 않는
장애물**이 되고, 살아 있는 에이전트는 그 앞에서 100% 책임을 지고 비켜야 한다.
게다가 `problem.deps` 의 선행자를 얼리면 그 HOI 가 영영 끝나지 않아
`pred_done` 이 계속 False 이고, 후속 에이전트는 `DEP_STANDOFF` 앞에 붙들린다.
이 기준선은 회피 비용을 **포함**하는 정도가 아니라, 실제 합동 롤아웃보다도
불리했다.

### A-1 의 세 질문에 대한 답

1. **어떤 경로를 쓰는가 — 문제 없었다 (확인).** 단독 롤아웃은
   `modes[0]`(canonical mode)을 쓰고, canonical 은 모든 에이전트에 route 0 을
   준다. `WorldModel._routes_for` 가 `out.sort(key=lambda r: r.length)` 로
   정렬하므로 **route 0 은 최단 경로다.** 자유 단독 궤적의 최단 경로 이탈이
   평균 0.111 m 인 것이 이를 실측으로 뒷받침한다. 지시서가 우려한 "원래 mode 를
   그대로 써서 혼자인데도 우회한다"는 **일어나고 있지 않았다.**
2. **VO 비용이 남아 있는가 — 남아 있었고, 이것이 진짜 원인이었다 (확인).**
   위 표대로 얼린 이웃은 `aij=1.0` 으로 VO 비용에 그대로 들어가고 안전 투영에도
   잡힌다. 이것이 정체 75.7% 를 만들었다.
3. **시작 상태가 원본과 같은가 — 같다 (확인).** 위치·속도·phase 를 그대로
   복사한다. 수정본은 산 에이전트의 것만 유지하고 나머지 속도를 0 으로 둔다
   (어차피 움직이지 않으므로 관측상 차이 없음).

### 고친 것

`scripts/collect_progress_labels.py` 의 `solo_state()`:

- 나머지 구성원을 **`FAR = 1e4` m 로 치운다.** VO 의 원거리 컷오프
  (`|w|² > (R + (v_i+v_j)·τ)²`)와 안전 투영의 seg-seg 거리를 모두 넘어서므로
  코드 경로를 건드리지 않고 장면에서 사라진다.
- **의존성 대기를 푼다** (`wp_out` 을 과거로). 남의 HOI 를 기다리는 것은 회피
  비용이 아니라 과업이고, 얼어붙은 선행자는 영원히 끝나지 않는다.
- 경로는 route 0(최단 경로)을 유지한다 — 위 1번대로 이미 옳았다.

**추론:** 이 결함은 라벨 정의 2번(클러스터 해체)의 `Δt_delay` 가 전부 음수였던
것과 직접 이어진다. 기준선이 실제보다 느렸으므로 `함께 − 혼자` 가 음수로
나오는 것이 당연했다. 다만 정의 3번(서브골)의 `y_exit=0.21%` 는 기준선이 아니라
도달 조건 자체의 문제이므로 이것만으로는 설명되지 않는다.

## B-2 — 다섯 결정과 근거

### 1. 합인가 최댓값인가 → **최댓값**을 주 라벨로, 합도 함께 저장

지시서 권장대로 makespan 이 마지막 한 명으로 정해지므로 최댓값을 주 라벨
(`loss_max`)로 쓴다. `loss_sum` 과 `loss_min` 도 매 행에 저장했다.

시범에서 잰 근거: **둘의 상관은 0.924** 로 높지만 같지 않다. 결정적으로
**`loss_max` 는 음수가 한 건도 없고 (0.0%), `loss_sum` 은 3.0% 가 음수다.**
합은 "한 명이 이득 본 것"이 "다른 한 명이 손해 본 것"을 상쇄해 회피 비용이
아닌 값이 섞인다. 최댓값에는 그 상쇄가 없다.

### 2. 직선인가 경로 호길이인가 → **경로 호길이** (`leg.remaining`)

직선거리는 장애물을 무시해 우회를 손해로 잡지 못한다. `Guide.remaining(idx)`
가 이미 있으므로 추가 비용이 없다.

**추가 결정: 자로는 항상 route 0(최단 경로)을 쓴다** — 단독 쪽과 합동 쪽
모두. 후보가 더 긴 경로를 고르면 그 자체가 손해여야 하는데, 각자 자기 경로의
호길이를 재면 긴 경로를 골라도 "그 경로 기준으로는 잘 나아간 것"이 되어
경로 선택 비용이 사라진다. 공통 자를 쓰면 우회가 손실로 잡힌다.
위치는 `project_full` 로 route 0 위에 투영한다.

**미확인 한계:** `project_full` 은 폴리라인 전체에서 최근접점을 찾으므로,
에이전트가 route 0 의 반대편 homotopy 로 크게 돌면 뒤쪽이 아니라 앞쪽 구간에
붙어 진행을 과대평가할 수 있다. 시범에서 route 0 이탈 중앙값이 0.111 m 라
현재 규모에서는 문제가 관측되지 않았으나, 진짜 측지거리와 대조하지는 않았다.

### 3. phase 전환 처리 → **전체 경로의 남은 호길이**

지시서 권장대로다. `remaining_on()`:

    TO_WP   -> leg1.remaining(proj) + leg2.length
    DWELL   -> leg2.length
    TO_GOAL -> leg2.remaining(proj)
    DONE    -> 0

10초 안에 waypoint 를 넘어가도 같은 척도의 단조 감소가 되어 전환이 저절로
이어진다. `WorldModel._to_go` 가 정체 판정에 쓰는 식과 같은 형태다.

### 4. DWELL 처리 → **별도 처리 없음. 상쇄되는 것을 확인했다**

DWELL 중 남은 호길이는 `leg2.length` 로 상수이므로 진행이 0 이다. 이것은 과업
이지 회피 비용이 아니다. 확인을 위해 `dwell_alone` / `dwell_together` 를
행마다 세어 저장했다 (창 안에서 waypoint 에 정확히 스냅된 스텝 수).

**시범 합계: 단독 41,832 스텝 vs 합동 23,189 스텝.** 상쇄되기는 하지만
**단독 쪽이 1.80배 많다** — 자유 단독이 waypoint 에 더 빨리 도착해 DWELL 을 더
많이 소화하기 때문이다. 방향이 손실을 **과소평가**하는 쪽이므로 (단독이 정지에
시간을 더 쓴다) 게이트 판정에는 보수적이다. 그대로 둔다.

쓰기에는 느슨하다. 이 단계에서는 게이트가 통과했으므로 반경을 건드리지 않고
기록만 남긴다.

## ⚠ 본 수집에서 C 게이트 1이 유지되지 않았다

**지시서가 지정한 시범(같은 20 인스턴스)에서 게이트 1은 62.0 % 로 통과했고,
그에 따라 D 로 진행했다. 그러나 격자 전체 1,620 인스턴스에서 같은 통계는
52.4 % 다.** 게이트 문턱 60 % 아래다. 이것을 숨기지 않고 그대로 보고한다.

D 의 새너티 6종에는 양수 비율 항목이 없고 6종은 전부 통과했으므로 본 수집
자체의 게이트는 통과했다. **지시서대로 다섯 번째 라벨 정의는 시도하지
않았고, 라벨 정의도 코드도 이 사실을 받고 고치지 않았다.**

### 어디서 갈렸나

| 층 | 행 | `loss_max` 중앙값 | 양수 비율 |
|---|---:|---:|---:|
| **k=2** | 137,128 (74.5 %) | 0.000 m | **48.7 %** |
| k=3 | 37,536 | 1.640 m | 61.2 % |
| k=4 | 9,408 | 3.338 m | 71.5 % |

| dep_mode / n | n=2 | n=3 | n=4 |
|---|---:|---:|---:|
| chain | 42.2 % | 54.9 % | **63.5 %** |
| fork | 42.2 % | 52.2 % | 54.3 % |
| none | **34.0 %** | 45.0 % | 51.4 % |

| phase_sig | 행 | `loss_max` 중앙값 | 양수 비율 |
|---|---:|---:|---:|
| `00` (둘 다 →waypoint) | 57,056 | 2.706 m | **76.0 %** |
| `000` (셋 다 →waypoint) | 14,992 | 4.018 m | **87.6 %** |
| `22` (둘 다 →goal) | 35,416 | 0.000 m | **19.4 %** |
| `222` | 6,512 | 0.000 m | 21.3 % |
| `02` / `20` | 19,092 | 0.000 m | 42.5 % |

**세 갈래가 같은 방향을 가리킨다:**

1. **k=2 가 전체의 74.5 %인데 양수 비율이 절반이다.** 시범의 20 인스턴스는
   n=3·4 비중이 커서 62 % 가 나왔다.
2. **`→goal` 국면(`22`)에서 양수 비율이 19.4 % 로 떨어진다.** 이 국면의 행이
   19 % 다.
3. 의존성이 없는 `none` 이 가장 낮다.

**클러스터 상태 단위로 보면 78.1 % (11,518 중)는 후보 16개 중 최소 하나가
양수 손실을 낸다. 21.9 % 는 후보 16개가 전부 정확히 0 이다.**

### 이것이 뜻하는 것 — 지시서의 두 갈래 대조

지시서는 게이트 1 미달이면 "A-1 의 기준선 문제가 남아 있거나, 회피가 실제로
진행을 방해하지 않는다는 뜻"이고 어느 쪽인지 A-1 결과와 대조하라고 했다.

**A-1 쪽은 아니다 (확인).** A-1 에서 기준선을 고쳤고, 그 결과 자유 단독이
얼린 단독보다 나쁜 경우가 0 %, 정체가 75.7 %→6.5 % 로 떨어졌으며,
`progress_alone` 은 본 수집 184,072 행에서 **음수가 한 건도 없고 0 인 행이
0.0 %** 다. 기준선은 이제 진행하고 있다. 기준선이 여전히 막혀 있다면
`progress_alone` 에 0 과 음수가 쌓였을 텐데 그렇지 않다.

**"회피가 진행을 방해하지 않는다" 쪽인데, 정확히는 "지금 클러스터로 묶인
쌍의 절반은 애초에 서로를 방해하지 않는다"이다 (추론).** 근거:

- 이 절반은 값이 작은 것이 아니라 **비트 단위로 정확히 0** 이다 — 합동
  롤아웃이 단독 롤아웃과 완전히 같은 궤적을 냈다는 뜻이고, 상호작용이 약한
  것이 아니라 **없다.**
- 그 분포가 k=2 · `→goal` 국면 · `none` 에 몰려 있다. 셋 다 "3 m 안에 있지만
  서로의 진로에 걸치지 않는" 상황이 흔한 조건이다.
- A-2 에서 후보 16개가 전부 같은 궤적을 낸 클러스터가 전부 k=2 였던 것과
  같은 현상이다.

즉 라벨이 아니라 **`R_interact = 3.0 m` 의 현재 위치 기준 근접 그래프가
상호작용을 과잉 포착한다**는 신호로 읽는다. S5-2 가 3.0 m 를 고른 것은
클러스터 **분할**을 위해서였고 (k=N 이 17.14 % 로 90 % 를 넘지 않는 값),
라벨링의 표본을 고르는 자로 쓰기에는 느슨하다. S5-2 보고서가 "예측 궤적 최소
거리는 더 정확할 수 있으나 rollout 을 추가로 요구하므로 이 단계에서는 쓰지
않았다"고 남겨 둔 것이 바로 이 지점이다 — 본 수집은 어차피 rollout 을 굴리고
있으므로 그 비용이 이미 지불돼 있다.

**다음 단계의 선택지 (이번 단계에서 실행하지 않았다).**
라벨 정의를 또 바꾸는 것이 아니라 **표본을 고르는 조건**을 손보는 쪽이다.

- 라벨은 그대로 두고 `loss_max == 0` 인 행을 "상호작용 없음"으로 명시적으로
  다루기 (분류 헤드의 3번째 클래스, 또는 회귀 표본에서 제외)
- 클러스터 판정을 현재 위치가 아니라 **예측 궤적 최소거리**로 바꾸기
- k=2 를 하향 표집해 층화 비중을 맞추기

어느 쪽도 새로운 라벨 정의가 아니므로 "네 번째 정의를 시도하지 않는다"는
제약에 걸리지 않는다. 다만 **지시받은 범위 밖이라 실행하지 않았다.**

## 예상과 달랐던 것

1. **단독 기준선이 합동보다 불리했다.** `PHASE_DONE` 을 "에이전트를 끄는
   스위치"로 읽었는데, 실제로는 "움직이지 않지만 100 % 비켜 줘야 하는
   장애물로 만드는 스위치"였다 (`safety/vo.py:79` 의 `aij = 1.0`). 정체
   75.7 % 는 예상보다 훨씬 나빴다. 앞선 세 시범의 `Δt_delay` 가 전부 음수였던
   증상의 상당 부분이 여기서 나왔을 것으로 본다 (**추론**).

2. **A-1 의 1번 질문(경로)은 문제가 아니었다.** 지시서가 가장 의심한 것이
   "혼자인데도 우회 궤적을 따라간다"였는데, canonical mode 가 이미 route 0 을
   주고 route 라이브러리가 길이순 정렬이라 최단 경로가 맞았다. 실제 원인은
   2번(VO 잔존)이었다.

3. **손실이 정확히 0 인 행이 이렇게 많을 줄 몰랐다.** 시범 38 %, 본 수집
   47.5 %. "작은 값"이 아니라 "비트 단위 0"이라 원인이 명확했다 — 합동과
   단독의 궤적이 완전히 같다.

4. **시범 20개가 대표성이 없었다.** 전부 `chain` 에 낮은 seed 였다. 게이트
   1 이 62.0 %→52.4 % 로 떨어진 것은 라벨이 바뀌어서가 아니라 표본이 바뀌어서다.
   앞선 세 시범도 같은 20개 위에서 판정했으므로, 그 판정들도 같은 편향을
   갖고 있었다.

5. **중복이 26.3 %나 됐다.** 같은 (클러스터 구성, 후보)가 연속된 재계획에서
   반복된다 — 1 초마다 재계획하는데 클러스터 구성과 위치가 소수점 둘째 자리
   해상도에서 자주 그대로다.

6. **`loss_sum` 에는 음수가 4.6 % 있는데 `loss_max` 에는 0.1 % 뿐이다.**
   B-2 결정 1(최댓값)이 예상보다 잘 맞았다. 합은 한 명의 이득이 다른 한 명의
   손해를 상쇄해 회피 비용이 아닌 값을 섞는다.

7. **DWELL 은 상쇄되지만 대칭이 아니었다.** 본 수집에서 단독 2,215,196 스텝
   vs 합동 1,940,174 스텝 (1.14 배). 자유 단독이 waypoint 에 더 빨리 닿아
   DWELL 을 더 많이 소화한다. 방향은 손실을 **과소평가**하는 쪽이라
   게이트 판정에 보수적이므로 그대로 두었다.

8. **route 0 호길이 자는 진짜 측지거리와 잘 맞았다** (교차확인, 61 (행,
   구성원) 표본): 상관 0.983, 차이 중앙값 −0.006 m. 다만 꼬리가 있다 —
   \|차이\|>0.1 m 가 29.5 %, >0.5 m 가 8.2 %, 최대 2.188 m. B-2 결정 2 에서
   우려한 `project_full` 의 과대평가는 드물지만 존재한다.
