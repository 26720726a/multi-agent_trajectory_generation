### A-1b. 정확한 가법 분해 (실제 단독 롤아웃, 층화 40 인스턴스 2,672 행)

| 기호 | 뜻 | 주행 경로 | 자 |

| `T0_i` | 합동 진행량 (= S5-3E 의 `prog_together`) | route r | route 0 |
| `loss_route_i` | **경로 선택으로 잃은 진행량** (혼자일 때) | | |
| `loss_avoid0_i` | **같은 경로에서 남을 피하느라 잃은 진행량** | | |

## B — 새 라벨: 회피 성분만 (구현하고 시범까지 감)

A-2 미달이므로 본래 §B 로 가지 않는다. 다만 지시서 원칙 2("미달했더라도 지정된
측정은 전부 수행한다")에 따라 정의·결정·시범을 전부 수행했다. **A-1b 의 정확한
분해와 새 라벨은 같은 단독 롤아웃 캐시를 쓰므로 추가 비용이 없었다.**

### B-1. 정의

자를 후보마다 바꾼다 — **후보가 배정한 자기 route 위에서 잰다.**

    base_i       = (route r_i 위) t=0 남은 호길이
    together_i   = base_i - (합동 롤아웃 t=H 의 route r_i 위 남은 호길이)
    alone_i      = base_i - (단독 롤아웃 t=H 의 route r_i 위 남은 호길이)
    loss_avoid_i = alone_i - together_i          <- 새 주 라벨

`base_i` 가 분자·분모에서 **정확히** 상쇄되므로 경로 선택 비용이 사라진다.
canonical 도 route 0 위에서 남을 피해야 하므로 `loss_avoid` 가 0 이 아니다.

### B-2. 경로 선택 비용은 버리지 않는다 — 별도 열

롤아웃이 필요 없다. t=0 의 남은 호길이 차이다:

    route_cost_i = (route r_i 위 t=0 남은 호길이) - (route 0 위 t=0 남은 호길이)

통합 시 `loss_avoid + w · route_cost` 로 합치면 된다. **모델은 롤아웃이 필요한
부분(회피)만 근사하고, 롤아웃이 필요 없는 부분(경로 길이)은 직접 계산한다**
— 계획서 §1.3 의 증류 프레이밍과 같다.

### B-3. 먼저 정한 네 가지

**결정 1 — 단독 기준선의 개수: `(구성원, route 색인)` 으로 캐싱한다.**

route 조합별로 캐싱하면 후보 16 개가 요구하는 서로 다른 키가 훨씬 줄어든다.
실측 (시범 40 인스턴스):

| | S5-3E | **S7** |
|---|---:|---:|
| 구성원당 단독 롤아웃 수 | 1.00 | **3.10** |
| 단독 롤아웃 총계 | (상태당 구성원 수) | 1,166 |
| 단독 시간 | — | 13.79 s |
| 합동 시간 | — | 112.00 s |
| **합동 대비 단독 추가 비용** | **3.80 %** | **12.32 %** |
| 시범 벽시계 (40 인스턴스, 2,672 행) | — | 279 s |

**확인: 후보마다 자를 바꾸는 대가는 단독 롤아웃 3.1 배(= 전체의 12.3 %)다.**
route 가 에이전트당 최대 4 종이므로 상한 4 배이고, 실측이 3.10 인 것은 16 개
후보가 4 종을 다 쓰지는 않기 때문이다 (추론).

**결정 2 — 양보 순서(rank)는 캐싱 키에 넣지 않는다.**

단독 mode 를 직접 만들어 쓴다: `PlanMode(route r at i, 항등 양보순서,
cautious=False, split_side=False)`. 혼자일 때 양보 순서 자체는 무의미하므로
이 키는 **정의상 정확하다.**

다만 코드를 따라가 보면 양보 순서가 두 경로로 혼자에게도 새어 든다 —
`speed_scale`(`planning/control.py:589`)과 `side_bias`(`:692`)가 rank 에서
파생된다. **그 대가를 실측했다** (`results/s7/solo_mode_flags.json`,
64 (구성원, 후보) 쌍): 후보의 플래그를 그대로 쓴 단독 진행량과 위 단독 mode 의
진행량 차이

| | 값 |
|---|---:|
| 정확히 0 인 비율 | 59.4 % |
| 차이 절댓값 중앙값 | **0.000 m** |
| 차이 절댓값 p90 / 최대 | 0.200 m / **0.200 m** |
| `split_side=False` 인 쌍의 최대 차이 | **0.000 m** |
| `split_side=True` 인 쌍의 중앙값 차이 | 0.075 m |

**확인: 차이는 `split_side` 에서만 나온다.** `sample_modes` 의 variants 가
`[(F,F), (F,T), (T,T)]` 라 `cautious=True` 는 항상 `split_side=True` 와 같이
오고, `split_side=False` 이면 단독 진행량이 **비트 단위로 같다.**
최대 0.200 m 는 10 초 창 진행량(중앙값 수 m) 대비 작다.

**남는 성질 (그대로 둔다):** 이 선택은 cautious 의 감속 비용과 side bias 비용을
`loss_avoid` **안에 남긴다.** 그 둘은 route 와 달리 "남이 없어도 치르는 비용"이
아니라 "남을 피하려고 미리 정하는 정책"이므로 회피 비용에 남는 것이 맞다고
본다 (추론).

**결정 3 — 음수를 clamp 하지 않는다.** 시범에서 `loss_avoid_max` 음수 비율은
**0.19 %** (5/2,672), 최소 −4.03 m 다. (옛 라벨은 0.41 %.)

**결정 4 — 분류 라벨은 `stalled` 를 유지한다.** 시범 비율 11.7 %
(`blocked` 12.3 %), 둘 다 5~95 % 안이다.

### 수집기가 옛 라벨을 재현하는지 (회귀 확인)

새 수집기는 같은 롤아웃에서 **S5-3E 라벨도 함께 낸다.** 겹치는 uid

### 게이트 1 은 라벨 재정의로 움직일 수 없다 (구조적 확인)

**canonical 은 전원 route 0 이므로 새 자 = route 0 = 옛 자다.** 따라서
**canonical 의 새 라벨 값은 옛 라벨 값과 정확히 같다** — 시범 40 인스턴스의
전원-route-0 후보 594 건에서 `|새 − 옛|` 최대 **0.0** (확인).

| canonical 의 손실 | 새 라벨 | 옛 라벨 |
|---|---:|---:|
| 0 이 아닌 비율 | **41.3 %** | **41.3 %** |
| 중앙값 / 평균 (m) | 0.000 / 0.957 | 0.000 / 0.957 |

## 진단 — 편향의 실제 출처는 자가 아니라 동점이다

지시서 C-3 은 미달 시 "A-1 의 분해 결과와 대조해 **회피 성분 자체가 후보를
구별하지 못한다**는 뜻인지 판단하라"고 했다.

### 그렇지 않다 — 회피 성분은 후보를 구별한다 (확인)

| | 값 |
|---|---:|
| 회피 성분이 차지하는 그룹 내 분산 비중 | **92.4 %** |
| 후보 간 `loss_avoid` 표준편차 중앙값 | **0.703 m** |
| 표준편차가 0 이 아닌 그룹 비율 | **79.0 %** |

### 그러면 무엇이 문제인가 — 동점 (확인)

`scripts/diag_route0_tie.py`. S6-4 §8 이 쓴 통계는 "**최소값 집합에** 전원
route 0 후보가 **하나라도** 있는가"다. 그 집합은 후보 하나가 아니다:

| | S5-3E 본 수집 (6,381 비퇴화 그룹) | 시범 40, 옛 라벨 | 시범 40, **새 라벨** |
|---|---:|---:|---:|
| 그룹 크기 평균 | 15.99 | 16.0 | 16.0 |
| **최소값 집합(동점)의 평균 크기** | **6.45** | 6.50 | 6.60 |
| 기저비율 p (임의 후보가 전원 route 0) | 16.6 % | 21.2 % | 21.3 % |
| **관측** P(최소값에 전원 route 0 포함) | **64.1 %** | 79.4 % | **72.0 %** |
| **귀무모형** (같은 동점 크기, 무작위) | **58.6 %** | 66.4 % | **67.4 %** |
| 기저비율 대비 배수 | 3.87 배 | 3.74 배 | 3.39 배 |
| **귀무모형 대비 배수** | **1.09 배** | **1.19 배** | **1.07 배** |
| **귀무모형 초과분** | **+5.4 %p** | **+13.0 %p** | **+4.5 %p** |

귀무모형은 "최소값 집합이 그룹의 후보 중 같은 크기의 균일 무작위
부분집합"이다: `1 − C(N−A, T) / C(N, T)`.

**확인 셋:**

1. **S6-4 §8 의 "3.8 배 과대표집"은 대부분 동점이 만든 착시다.** 동점 크기를
   고정하면 3.87 배가 **1.09 배**로 내려간다. 기저비율 16.6 % 짜리 사건을
   평균 6.45 번 시행하면 "하나라도"가 58.6 % 가 되는 것은 산수다.
2. **새 라벨은 남은 실제 이점을 실제로 줄인다** — 귀무모형 초과분
   +13.0 %p → **+4.5 %p** (65 % 감소). **B-1 의 정의 자체는 의도대로 작동한다.**
3. **그런데 줄일 것이 애초에 작아서 최종 지표가 거의 안 움직인다** —
   교사 최적이 canonical 인 비율 66.4 % → 59.8 % (문턱 40 %).

### 동점을 걷어내면 라벨을 바꾸지 않아도 통과한다 (확인)

**최소값이 0 이 아닌 그룹(= 실제로 회피 비용이 발생한 그룹)만** 보면:

| 교사 최적이 canonical 인 비율 | 전체 비퇴화 그룹 | **최소값 > 0 인 그룹만** |
|---|---:|---:|
| **S5-3E 본 수집, 옛 라벨** | 54.4 % (n=6,344) | **26.1 %** (n=2,171) |
| 시범 40, 옛 라벨 | 66.4 % (n=131) | 58.7 % (n=46) |
| 시범 40, 새 라벨 | 59.8 % (n=132) | 44.7 % (n=38) |

**본 수집 규모에서 옛 라벨 그대로도 26.1 % 다 — C-2 문턱 40 % 를 라벨 재정의
없이 통과한다.** (시범 40 의 값이 높은 것은 그룹이 38~46 개뿐이라 그렇다 —
표본이 작다.)

**추론: 모델이 canonical 을 못 이기는 원인은 라벨의 자가 아니라, 학습·평가
표본의 절반이 "후보를 무엇으로 고르든 결과가 같은" 그룹이라는 데 있다.**
그런 그룹에서 canonical 은 동점으로 자동 정답이 되고, 어떤 모델도 그보다
잘할 수 없으며, S6-5 §4 가 보인 "easy 층에서 모델이 canonical 에게 지는"
구조가 바로 그것이다.

### (a)~(d) 정리

| 원인 후보 | 판정 | 근거 |
|---|---|---|
| (a) 특성 충돌 | 기각 (S6-3) | 오라클 regret 0.00034 m |
| (b) 표본/용량 | 기각 (S6-3 D2) | 18배 축소로 val 이득 0 |
| (c) 표현 | 부분 확인, 불충분 (S6-4) | tau-b 는 올랐고 top-1 은 불변 |
| **(d) 라벨의 route 0 편향** | **거의 기각 (S7)** | 경로 성분은 분산의 16.7 %, 귀무모형 대비 이점 1.09 배. 새 라벨로 초과분을 65 % 줄여도 최종 지표가 안 움직인다 |

`loss == 0` 행을 상호작용 없음으로 명시 처리, 클러스터 판정을 예측 궤적
최소거리로, k=2 하향 표집. **어느 것도 이번 지시서의 범위가 아니므로
실행하지 않았다.**

## 예상과 달랐던 것

1. **`loss_route` 가 86.2 % 의 관측에서 정확히 0 이었다.** S5-3E B-2 결정 2 가
   "공통 자를 쓰면 우회가 손실로 잡힌다"고 한 논리는 맞지만, **10 초 창
   안에서는 거의 잡히지 않는다.** `project_full` 이 폴리라인 전체에서
   최근접점을 찾으므로 두 경로가 갈라지기 전까지는 같은 진행량이 나온다.
2. **`loss_route` 에 음수(8.1 %)가 양수(5.6 %)보다 많았다.** 더 긴 경로로
   가는 것이 route 0 자 위 투영 진행량을 **늘리는** 경우가 더 흔하다.
   부호가 뒤집히는 방향이라 예상 밖이었다.
3. **canonical 의 라벨 값이 재정의로 전혀 변하지 않는다는 것을 게이트 C-1 을
   세우고 나서야 알았다.** 전원 route 0 이면 새 자 = 옛 자이므로 구조적으로
   같다. C-1 은 라벨이 아니라 표본을 재는 게이트였다.
4. **"3.8 배 과대표집"이 대부분 동점이었다.** S6-4 §8 → S6-5 → S7 지시서로
   이어진 전제의 핵심 근거였는데, 동점 크기를 고정한 귀무모형과 대조하자
   1.09 배로 내려갔다. 귀무모형을 세우기 전에는 이 숫자를 그대로 믿고 있었다.
5. **새 라벨이 의도대로 작동하는데도 소용이 없었다.** 귀무모형 초과분을
   65 % 줄였다 — 정의는 옳게 작동한다. 줄일 편향 자체가 작았을 뿐이다.
6. **단독 기준선 비용이 3.1 배로 그쳤다.** route 가 4 종이라 최대 4 배를
   각오했는데, 후보 16 개가 4 종을 다 쓰지는 않는다.
7. **`split_side` 만이 혼자 있는 에이전트의 궤적을 바꿨다.** `cautious` 도
   `speed_scale` 로 영향을 줄 줄 알았는데, `sample_modes` 가 `cautious=True` 를
   `split_side=True` 와만 짝짓기 때문에 따로 분리되지 않는다.
8. **26 uid 로는 split 간 분포가 전혀 맞지 않았다** (`stalled` train 13.9 % vs
   test 0.9 %). S6 §12-7 이 1,126 uid 에서 본 격차가 26 uid 에서는 훨씬 크다.
9. **층화해 뽑은 40 개 중 14 개가 행을 한 줄도 내지 않았다.** 클러스터가
   한 번도 생기지 않는 인스턴스가 `n_agents=2` 쪽에 몰려 있어, 층화의
   의도와 반대로 표본이 큰 쪽으로 기울었다.

## 남은 불확실성

- **A-1b 정확 분해를 40 인스턴스에서만 했다.** A-1a 대리 분해는 전체
  135,597 행에서 1.0 % 로 더 작게 나왔고 방향이 같지만, 정확 분해의
  16.7 % 가 격자 전체에서도 유지되는지는 재지 않았다. 60 % 문턱과의 거리가
  크므로 판정이 뒤집힐 가능성은 낮다고 본다 (추론).
- **동점 귀무모형은 "최소값 집합이 무작위 부분집합"을 가정한다.** 실제로는
  동점의 원인(상호작용 없음)이 route 배정과 약하게 상관될 수 있고, 그 경우
  귀무모형이 이점을 조금 과대평가한다. 관측 초과분 +5.4 %p 는 그 상한이다.
- **`route_cost` 의 가중치 w 를 정하지 않았다.** 통합 규칙
  `loss_avoid + w · route_cost` 는 정의만 해 두었고, w 를 고르는 것은 별개
  축이다. `route_cost` 와 `loss_avoid` 의 상관은 시범에서 +0.159 다
  (긴 우회가 회피 손실을 **줄이는** 방향이면 음수여야 하는데 양수다 —
  해석하지 않았다).
- **본 수집을 돌리지 않았으므로 새 라벨의 격자 전체 통계는 없다.**
  시범 40 의 값(교사 최적 canonical 59.8 %)이 1,620 인스턴스에서 얼마가
  되는지는 모른다. S5-3E 에서 같은 통계가 시범 62.0 % → 본 수집 52.4 % 로
  10 %p 움직인 전례가 있다.
- **시범 표본이 의도한 층화대로 서지 않았다.** 40 개를 층화해 뽑았으나 26 개만
  행을 냈고, 그 26 개는 `n_agents` 가 큰 쪽에 치우쳤다 (n2 6 / n3 11 / n4 9).

  C 게이트 값을 본 수집 규모의 값으로 읽으면 안 된다.
- **`stalled` 가 test 에서 0.9 % 인 것은 26 uid 표본의 산물일 가능성이 크지만
