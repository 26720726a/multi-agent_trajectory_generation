## 3. 무엇을 바꿨는가 (배치 2)

```python
if not np.any(keep):
    sp_prev = float(np.linalg.norm(vel[i]))
    if WIPEOUT_DECELERATE and sp_prev > dv_max:
        v_cmd[i] = vel[i] * (1.0 - dv_max / sp_prev)   # 방향 유지, 크기만 감소
    else:
        v_cmd[i] = 0.0
    forced[i] = True
    continue
```

### 3-1. 구현 시 정한 것 — 셋 다 지시서 권장대로

1. **방향 유지.**  크기만 `dv_max = a_max·dt` 줄인다.  `v_pref` 쪽으로 트는
   것은 또 하나의 축이므로 하지 않았다.  테스트가 `cross(v_prev, v_cmd) = 0` 을
   못 박는다.
2. **`_project_safe` 순서 유지.**  감속이 투영보다 먼저다.  소스 인덱스를
   비교하는 테스트로 고정했다.
3. **연속 전멸은 매 스텝 `dv_max` 씩** 줄어 최대 4 스텝(0.40 s ≤ 사양 0.67 s)에
   선다.  그동안 계속 움직이는 것이 의도였다 — **그것이 게이트 2 를 깼다.**

`wipeout_decelerate` 를 config 에 넣어 `phys_fp` 가 갈리게 했다
(S3-A‴ §8-6 의 교훈).

### 3-2. 게이트 1 — `a_max = inf` 재현

`dv_max = inf` 면 `sp_prev > dv_max` 가 항상 거짓이라 즉시 정지 경로로 간다.
**별도 분기 없이** 원본 동작이 나온다.

```
compare_traj.py  ->  mismatched arrays: 0 / RESULT: IDENTICAL
check_wm.py      ->  md5 e1f2841f2f241abb48c1d11248dc4b6e (원본 v0 와 동일)
```

## 6. 게이트 2 미달 — 충돌 인스턴스 덤프

### 6-1. 무엇이 깨졌는가

| | 에이전트 간 | 장애물/벽 |
|---|---|---|
| 하한 | `min_sep = 0.70` | `radius = 0.30` |

| **B3 최소 clearance** | 0.7001 | **0.2436** |
| **B3 침범 행 수** | **0** | **88 (1.81%)** |

**에이전트 간 충돌은 0 이다.**  `_project_safe` 가 구조적으로 막는다.
깨진 것은 **장애물/벽**이다.

### 6-2. 최악 인스턴스의 감속 구간

`n2_none_72203b7a` ps=2, `obstacle_clearance = 0.2436`:

```
     t  |v_prev|  |v_cmd|  |dv|/dt    전멸      장애물거리   여유(radius)
    61     1.200    1.200     0.00 False     0.4573     +0.1573
    62     1.200    1.200     0.00 False     0.4263     +0.1263
    63     1.200    1.200     0.00 False     0.3812     +0.0812
    64     1.200    0.900     3.00  True     0.3259     +0.0259     <- 전멸 시작
    65     0.900    0.600     3.00  True     0.2844     -0.0156 !!  <- 침범
    66     0.600    0.300     3.00  True     0.2567     -0.0433 !!
    67     0.300    0.000     3.00  True     0.2436     -0.0564 !!  <- 최악
    68     0.000    0.000     0.00  True     0.2436     -0.0564 !!
```

t=64 에 전멸이 시작될 때 여유가 이미 **0.0259 m** 뿐인데, 서는 데 필요한
거리는 0.180 m 다 (S3-A″ §5-3).  감속하며 4 스텝 동안 0.082 m 를 더 들어가
`radius` 를 0.0564 m 침범한다.

### 6-3. 왜 아무도 막지 않는가 — 구조적 이유

**전멸은 "후보 65개가 전부 기하 필터에 걸렸다" 는 뜻이다.**  그런데 감속
fallback 은 **그 필터를 거치지 않고** `v_prev` 방향으로 계속 움직인다.

그리고 `safety/project.py::_project_safe` 는 **쌍 (i, j) 의 스윕 거리만** 본다.
장애물은 그 함수에 아예 없다 — `step()` 의 하드 필터(`free_steps`)가 막는
책임을 진다.  그 필터를 우회하면 장애물을 막는 것이 하나도 없다.

지시서 §3-2 는 "투영이 이 결과를 받아 안전을 지켜야 한다" 고 했지만,
**투영은 에이전트 간 안전만 지킨다.**  이 사실을
`tests/test_braking.py::test_the_safety_projection_does_not_cover_obstacles` 로
못 박아 두었다.

**결론: 이 구조가 바뀌지 않는 한 "전멸했는데 계속 움직이는" 처방은 전부 같은
문제를 만든다.**  감속 이동도 기하 필터를 통과하게 만들어야 하고, 그것이
B2(다단계 필터)의 일이다.  지시서가 "감속 중 움직이는 것이 위험하다면 B3 는
폐기하고 B2 로 간다" 고 미리 정해 둔 그대로다.

### 6-4. 되돌렸다

`wipeout_decelerate = False`.  코드는 남겼다 — 켜려면 무엇이 필요한지
config 주석에 적어 두었다.  5종 시나리오가 A⁴ 와 **완전히 동일**한 것으로
복원을 확인했다 (crossing2 위반 6/전멸 3, fork3 14/7 등).

`phys_fp` 는 `987f93051fbe` 로 A⁴(`1f9fc93a5969`)와 다르다 — 동작이 달라서가
아니라 **필드가 추가되어서**다.  다음 단계에서 A⁴ 를 기준선으로 쓰려면
재실행이 필요하다 (또는 `A4_nogeom.csv` 를 그대로 쓰되 지문 차이를 알고 쓴다).

## 7. 예상과 달랐던 것

### 7-1. 충돌률 지표가 아무것도 검사하지 않고 있었다 (가장 중요)

`scripts/summarize_run.py` 는 충돌률을 `status == "invalid"` 로 셌다.
그런데 `bench/run.py::run_instance` 는

```python
_fill(r, ...)                       # rep.valid 가 False 면 status = "invalid"
...
if not res.traj.feasible:
    r["status"] = f"unfinished:{res.note}"   # <- 덮어쓴다
```

**완주 실패면 검증 실패 표시가 덮어쓰인다.**  실제로 여섯 배치 전부에서
`status == "invalid"` 가 **0 행**이고, `valid == False` 인 행은 100% 가
`unfinished:deadlock` 이었다.

즉 **S3-A 부터 A‴ 까지의 "충돌 0건" 판정은 항상 0 이 나오는 열을 본 것이다.**

`agent_clearance` / `obstacle_clearance` 로 다시 판정했다:

| 배치 | 에이전트 침범 | 장애물 침범 | `agent_clr` 최소 | `obst_clr` 최소 |
|---|---|---|---|---|
| baseline_S2 | 0 | 0 | 0.7001 | 0.3200 |
| A_amax3 | 0 | 0 | 0.7001 | 0.3200 |
| A2_braking | 0 | 0 | 0.7001 | 0.3200 |
| A3_brakedist | 0 | 0 | 0.7001 | 0.3200 |
| A4_nogeom | 0 | 0 | 0.7001 | 0.3200 |
| **B3_decel** | **0** | **88** | 0.7001 | **0.2436** |

**이전 판정의 결론은 옳았다** (A⁴ 까지는 실제로 충돌 0).  그러나 **지표가
무효였으므로 운이 좋았던 것이지 검증된 것이 아니었다.**  B3 가 처음으로 진짜
충돌을 냈고, 그제서야 지표가 작동하지 않는다는 것이 드러났다.

`summarize_run.py` 를 clearance 기반으로 고쳤고, 에이전트/장애물을 나눠 낸다.
`bench/run.py` 의 status 덮어쓰기 자체는 **고치지 않았다** — CSV 스키마를
바꾸는 일이고 별도 축이다.  `valid` 열과 두 clearance 열이 이미 있으므로
분석 쪽에서 해결된다.

### 7-2. 전멸 건수가 31배가 되었다

4배 정도를 예상했다 (감속 4 스텝).  실제 +2992%.  감속-정지-재가속-재전멸
사이클이 도는 것으로 보인다 (추론, §5-2).

### 7-3. `n_amax_viol_project` 가 예상대로 늘었다

지시서 §6 이 "늘지 않으면 예상 밖" 이라고 했는데 **+219.4%** 로 늘었다.
예상이 맞은 드문 항목이다.

### 7-4. 사양을 지키자 성능이 무너졌다

계획서 §3.3-7 을 정확히 구현했더니 성공률이 22%p 떨어졌다.  **사양이
현행 알고리즘과 양립하지 않는다**는 뜻이다 — 사양이 틀렸다기보다, 사양을
지키려면 하드 필터 쪽도 함께 바뀌어야 한다 (추론).

## 8. 정리 — 무엇이 확정됐고 다음은 무엇인가

**확정된 것**

1. **B3 폐기.**  게이트 2(충돌)를 깼다.  장애물/벽 침범 88행, 최악 0.2436 m.
2. **구조적 이유가 있다.**  전멸 fallback 은 기하 필터를 우회하고,
   `_project_safe` 는 장애물을 다루지 않는다.  "전멸했는데 계속 움직이는"
   처방은 전부 같은 문제를 만든다.
3. **사양 위반 자체는 고칠 수 있다** (전멸 위반 −99.9%).  단 그것만으로는
   안 되고 하드 필터가 함께 바뀌어야 한다.
4. **`d_geom` 제거는 무해했다** (성공률 −0.10%p, p=0.59).  A⁴ 를 유지한다.
5. **충돌률 지표가 무효였다** (§7-1).  고쳤고, 이전 배치를 전부 재판정해
   A⁴ 까지는 실제로 충돌 0 임을 확인했다.

**다음 — B2 (다단계 필터)**

S3-A″ 가 원래 지목한 것이고, 이번 결과가 그 판단을 강화한다.  감속 이동이
기하 필터를 통과하게 만들려면 필터가 **여러 스텝을 내다봐야** 한다.
필요한 깊이는 이미 측정되어 있다 — **4 스텝 = 0.18 m** (S3-A″ §5-3).

**여전히 열려 있는 것**

* S3-A″ §9: 급정거형 전멸이 0건인데도 실패하는 7.0% 의 원인.
* `bench/run.py` 의 status 덮어쓰기 (분석 쪽에서 우회했지만 CSV 자체는 그대로).
