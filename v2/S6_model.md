## 요약

A1·A2·A3 세 방식을 전부 학습했고 지정된 측정을 전부 수행했다.

- **순열 불변성 통과** — 최대 차이 **1.43e-06** (문턱 1e-5).
- **top-1 regret 은 무작위보다 유의하게 낫다** — 세 방식 모두, val·test 양쪽에서
  95% 부트스트랩 구간이 0을 넘지 않는다. **게이트 통과.**
- **분류 AUC 는 0.78 에 미달한다** — val 0.663~0.717, test 0.650~0.677.
  지시대로 멈추지 않고 기록하고 진행했으며 층별로 분해했다.
- **그러나 모델은 canonical 후보(`mode_idx=0`)를 이기지 못한다.** 지시서가

  canonical 보다 **유의하게 나쁘다.** A3 만 무승부다. 이것을 숨기지 않고 보고한다.
- **채택: A3 (3-클래스).** 근거는 §3 에 적었고, val 에서 A1·A2·A3 의 차이가
  통계적으로 구별되지 않는다는 사실도 함께 적었다.

## 0. 입력을 다시 만들어야 했다 (지시서 §B 이행 과정)

계획서 §5.2 가 요구한 에이전트 토큰은 위치(2) + 속도(2) + **로컬 서브골(2)** +
phase 원핫(4) + 후보 mode 다. 그런데 `results/labels/main_progress_dedup.csv`
의 `agent_tokens` 는 **8차원**뿐이다 — `[위치−중심(2), 속도(2), phase 원핫(4)]`.
**서브골이 없고 후보 mode 도 토큰에 없다.**

서브골은 CSV 에서 복원할 수 없다. 절대좌표(waypoint 또는 goal)를 클러스터
중심 기준으로 바꿔야 하는데, CSV 에는 중심을 이미 뺀 값만 있어 중심 자체를
알 수 없기 때문이다.

**라벨은 다시 만들지 않았다.** rollout 없이 `run_wm_planner(seed=0)` 만 다시
돌려 `res.states` 를 얻는 `scripts/augment_subgoals.py` 를 새로 썼다. 라벨
수집이 쓴 것과 같은 궤적인지 확인할 수 있다 — 재도출한 절대위치에서 중심을
빼면 CSV 의 로컬 위치와 같아야 한다.

| | 값 |
|---|---:|
| 처리 uid | 1,126 (라벨 CSV 에 나오는 전부) |
| 벽시계 | **14.9 분** (16 병렬, 최대 shard 894 s) |
| **재도출 위치 vs CSV 로컬 위치 최대 오차** | **5.50e-06 m** (135,597행 전부) |

**확인:** 5.50e-06 m 은 CSV 가 소수 5자리로 반올림된 것과 정확히 같은 크기다.
플래너 재실행이 라벨 수집과 **비트 수준으로 같은 궤적**을 냈다.

서브골 정의는 `planning/control.py:585` 의 `target_pt` 와 같게 뒀다 —
`TO_WP` 면 waypoint, 나머지(DWELL/TO_GOAL/DONE)면 goal.

### 최종 입력 (계획서 §5.2)

에이전트 슬롯 **8** × **15차원**

| 칸 | 내용 |
|---|---|
| 0:2 | 위치 (클러스터 중심 기준 로컬) |
| 2:4 | 속도 |
| 4:6 | **서브골** (같은 로컬 프레임) |
| 6:10 | **phase 원핫 4** `[TO_WP, DWELL, TO_GOAL, DONE]` |
| 10:14 | route 원핫 4 — 후보 mode 가 이 에이전트에 준 경로 |
| 14 | yield rank / (n−1) — 후보 mode 의 양보 순서 |

장애물 슬롯 **8** × **4**: 중심(2, 로컬) + **half-extents(2)**. 외접원 근사를
쓰지 않았다. 관측된 장애물 수는 1~5개다.

CLS **4**: `k`, 국소 밀도, `cautious`, `split`.

후보 mode 문자열(`r0102|B>A>C>D|s`)을 풀어 **에이전트마다 다른 부분(route,
rank)은 토큰에, 후보 전체에 걸리는 부분(cautious/split)은 CLS 에** 넣었다.
계획서 §5.1 의 "전역 특성은 CLS" 원칙을 그대로 적용한 것이다. **후보 mode 를
어딘가에 넣지 않으면 같은 클러스터의 16개 후보가 입력상 완전히 같아져
top-1 regret 자체가 정의되지 않는다.**

**`cost` 순위는 넣지 않았다** (지시서대로 — 롤아웃을 돌려야 나오는 값이다).

### 발견: `density` 는 `k` 의 상수배다

`collect_progress_labels.py:176` 이 `density = k / (π · R_interact²)` 로
저장한다. `R_interact` 는 3.0 m 고정이므로 `density = k / 28.274` 다.
**즉 CLS 의 "국소 밀도"는 `k` 와 완전히 같은 정보이며 독립 특성이 아니다.**
계획서 §5.2 의 지시를 그대로 따르기 위해 두 칸 모두 넣었지만, **CLS 가 실제로
나르는 전역 정보는 (k, cautious, split) 세 가지뿐이다** (확인).

### 정규화

train 의 **유효 슬롯만으로** (패딩 제외) 연속 차원의 평균/표준편차를 내고
val/test 에 같은 통계를 적용한다. 원핫·rank·플래그는 건드리지 않는다.
**회귀 타깃도 train 통계로 표준화했다** — 미터 원 단위(σ≈2.9 m)로 두면
MSE 가 BCE 보다 커져 λ=1.0 이 의도대로 동작하지 않는다.

## 2. A 세 방식 — `loss_max = 0` 을 어떻게 다룰 것인가

train 에서 `loss_max = 0` 인 행은 **47.3%** 다 (val 58.6%, test 57.3%).

| # | 방식 | 회귀 손실에 들어가는 행 | 분류 |
|---|---|---:|---|
| A1 | 그대로 | 100 % | `stalled` 2진 |
| A2 | 회귀에서 제외 | **52.6 %** (`loss_max > 0`) | `stalled` 2진 |
| A3 | 3-클래스 | **42.2 %** (클래스 1 만) | 3-클래스 |

A3 클래스 정의와 train 비율:

| 클래스 | 정의 | train |
|---|---|---:|
| 0 상호작용 없음 | `loss_max == 0` | 47.3 % |
| 1 정상 | 나머지 | 42.2 % |
| 2 정체 | `loss_max ≠ 0` 이고 `stalled` | 10.5 % |

**"상호작용 없음"에 우선순위를 뒀다.** `loss_max` 가 비트 단위로 0 이면 합동
롤아웃과 단독 롤아웃의 궤적이 완전히 같다는 뜻이므로 (S5-3E §D), 그 행이
`stalled` 이더라도 그 정체는 **회피가 만든 것이 아니다.** 전체 행의 2.32%가
이 겹침에 해당한다.

### 순위 점수

top-1 regret 은 후보를 **점수 최소**로 고른다.

- A1 / A2 — 회귀 출력 ŷ 그대로.
- A3 — `P(정상)·ŷ + P(정체)·L̄₂` (L̄₂ = train 클래스 2 의 평균 loss).
  A3 의 회귀 헤드는 "정상" 행에서만 학습되므로 그대로 쓰면 편향된다.

A3 는 **이 결합이 실제로 이득이다** (확인): 회귀 출력만 쓰면 regret 이
val 0.783→0.895, test 0.739→0.984 로 나빠진다.

**A2 에는 이 결합을 만들 수 없다** — A2 의 분류 헤드는 `stalled` 를 예측하지
`loss_max > 0` 을 예측하지 않으므로, 회귀 헤드가 학습되지 않은 영역
(`loss_max = 0` 인 47%)에 대해 확률로 보정할 방법이 없다. **A2 는 회귀 헤드를
학습 분포 밖에서 쓴다** (추론). test 회귀 RMSE 가 이를 보여준다 — `loss = 0`
인 행에서 A2 3.827 m, A1 1.448 m 다.

### 결정과 그 한계

**A3 을 채택한다.** 근거는 세 가지이고, 셋째는 test 를 본 것이므로 선택
근거가 아니라 확인으로만 쓴다.

1. **val 의 top-1 regret 이 셋을 구별하지 못한다** (위 표). 지시서가 정한
   결정 기준만으로는 결정이 되지 않으므로 다른 근거가 필요하다.
2. **A3 만이 47%의 0 질량을 명시적으로 모형화한다.** "상호작용 없음" 클래스의
   AUC 는 val 0.810 / test 0.811 로, 그 질량이 **실제로 예측 가능하다**는 것을
   보여준다. A1 은 그것을 회귀로 눌러 담고 (그래서 `loss>0` 행의 RMSE 가
   3.027 m 로 가장 나쁘다), A2 는 버린다 (그래서 `loss=0` 행에서 3.797 m 로
   가장 나쁘다). A3 만 두 영역 모두에서 중간이다. 그리고 A3 의 순위 점수만이
   세 헤드를 결합한 **제대로 된 기댓값**이다.
3. (확인용) **test 에서 A3 이 A1·A2 보다 유의하게 낫고, canonical 에 지지
   않는 유일한 방식이다.**

**지시서는 A2 를 기본으로 봤지만 A2 를 채택하지 않았다.** A2 는 val·test
양쪽에서 top-1 regret 이 셋 중 가장 나쁘고 (유의하지는 않다), test 에서
canonical 보다 유의하게 나쁘다. §2 의 이유대로 A2 는 회귀 헤드를 학습
분포 밖에서 쓰는 구조적 결함이 있다.

무승부다. **모델을 붙여서 얻는 것이 지금은 없다** — 무작위 대비 개선의 대부분은
"canonical 을 고르는 것"만으로도 얻어진다 (canonical − 무작위: val −0.454,
test −0.643, 둘 다 유의).

**추론:** canonical 이 강한 것은 우연이 아니다. canonical 은 전원 최단 경로에
감속 없음이라 회피 손실의 정의(최단 경로 위 진행량 손실)와 직접 맞물린다.
S5-3E 가 정한 라벨은 "route 0 을 공통 자로 쓴다"이므로 **route 0 을 쓰는 후보가
구조적으로 유리하다.** 모델이 이 규칙성을 배우기보다 잡음을 배우고 있다.

## 7. 회귀 RMSE — 게이트를 문자 그대로 잴 수 없다

지시서의 기준은 "**교사 대비 2배 이내**"인데, **이 단계에는 교사의 예측이
없다.** P3-2 에서 교사는 `makespan_est` 라는 별도의 휴리스틱 추정값이었고
모델은 그것을 증류했다. S6 의 `loss_max` 는 **롤아웃으로 직접 잰 값 자체**이며
교사의 오차는 정의상 0 이다. 0 의 2배는 0 이므로 기준이 성립하지 않는다.

**대신 상수 예측(train 평균) 기준선과 라벨 표준편차를 함께 낸다.** 이것을
대체 기준으로 명시하고, 원래 게이트는 "판정 불가"로 남긴다.

| val | RMSE 전체 | `loss>0` 행 | `loss=0` 행 |
|---|---:|---:|---:|
| A1 | **2.233** | 3.027 | **1.427** |
| A2 | 3.336 | **2.535** | 3.797 |
| A3 (채택) | 3.019 | 2.556 | 3.305 |
| 상수(train 평균) 기준선 | 3.791 | 2.694 | — |
| 라벨 표준편차 | 2.495 | 2.614 | — |

| test | RMSE 전체 | `loss>0` 행 | `loss=0` 행 |
|---|---:|---:|---:|
| A1 | **2.430** | 3.315 | **1.448** |
| A2 | 3.394 | **2.703** | 3.827 |
| A3 (채택) | 3.080 | 2.736 | 3.311 |
| 상수 기준선 | 3.775 | 2.715 | — |
| 라벨 표준편차 | 2.584 | 2.661 | — |

**확인:** 세 방식이 각자 학습한 영역에서만 상수 기준선을 이긴다. A1 은 전체에서
(2.43 < 3.78), A2·A3 는 `loss>0` 행에서 겨우 (2.70·2.74 vs 2.72) 이긴다.
**A2 의 `loss>0` RMSE 2.703 m 는 그 층의 라벨 표준편차 2.661 m 보다 크다** —
그 영역에서 A2 는 평균 예측만도 못하다 (test 기준). 회귀 헤드는 약하다.

## 8. 데이터 규모 곡선 (A2, 지시서 §C)

train uid 를 시드 고정으로 부분 표집했다.

| train | uid | 행 | best epoch | val AUC | val regret(전체/비퇴화) | test AUC | test regret(전체/비퇴화) |
|---|---:|---:|---:|---:|---|---:|---|
| 25 % | 152 | 23,251 | 0 | 0.6164 | 0.773 / 1.119 | 0.5709 | 0.738 / 1.030 |
| 50 % | 304 | 47,049 | 0 | 0.6306 | 0.809 / 1.171 | 0.6248 | 0.805 / 1.123 |
| 100 % | 608 | 94,949 | 3 | **0.7172** | 0.806 / 1.166 | **0.6744** | 0.863 / 1.204 |

**확인: AUC 는 데이터에 반응하지만 top-1 regret 은 반응하지 않는다.**
AUC 는 0.616→0.631→0.717 (val), 0.571→0.625→0.674 (test)로 단조 증가한다.
그런데 regret 은 25 %가 100 %보다 오히려 낮다 (test 0.738 vs 0.863).

**"50 %와 100 %가 비슷하면 데이터는 충분하다"는 판정 기준에 대해:**
AUC 로 보면 50→100 의 개선(+0.087 val, +0.050 test)이 25→50(+0.014, +0.054)
보다 크거나 비슷하다 — **분류에 대해서는 곡선이 꺾이지 않았고 데이터가
부족하다** (추론). regret 으로 보면 데이터를 늘려도 나아지지 않는다 —
**후보 순위 매기기는 데이터 양의 문제가 아니다** (추론). 두 지표가 반대
방향이므로 "데이터가 충분한가"에 한 줄로 답할 수 없다.

**best epoch 이 25 %·50 %에서 0 이다.** 첫 epoch 이 끝난 시점이 val 최저였고
그 뒤로는 계속 나빠졌다. 100 %에서도 3 이다.

## 10. split 누수 재확인 (지시서 §C)

"val 손실이 train 보다 크게 낮으면 split 이 새는 것"이라 다시 봤다.

| 검사 | 결과 |
|---|---|
| uid 교집합 | train∩val 0, train∩test 0, val∩test 0 |
| 클러스터 상태 그룹이 두 split 에 걸친 경우 | **0** |
| A2 최적 체크포인트 AUC | **train 0.805 > val 0.717 > test 0.674** |
| A2 최적 체크포인트 `loss>0` RMSE | **train 2.173 < val 2.535 < test 2.703** |

**확인: 누수 없다.** val 이 train 보다 좋은 방향이 아니라 정확히 반대다.
학습 로그에서 epoch 0 의 val 손실이 train 보다 낮아 보이는 것은 train 손실이
**그 epoch 동안의 평균**(모델이 개선되는 중)이고 val 은 **epoch 끝의 값**이기
때문이다.

## 11. 진단 — 왜 이렇게 일찍 멈추는가

세 방식 모두 best epoch 이 1~3 이다. 두 가지를 쟀다
(`learn/diagnose.py`, `results/s6/diag_variance.json`).

### 유효 표본은 행 수가 아니다

| split | 행 | **클러스터 상태(그룹)** | 행/그룹 |
|---|---:|---:|---:|
| train | 94,949 | **5,937** | 16.0 |
| val | 20,301 | 1,271 | 16.0 |
| test | 20,347 | 1,274 | 16.0 |

**한 그룹의 16 행은 토큰 특성이 거의 같다** — 위치·속도·서브골·phase·장애물이
전부 동일하고 route 원핫(4) · rank(1) · cautious/split(2) 만 다르다.
**즉 독립 표본에 가까운 것은 94,949 가 아니라 5,937 이다.** 파라미터
434,690 개를 5,937 개 장면으로 맞추고 있으니 1~3 epoch 만에 과적합하는 것이
이상하지 않다 (추론).

### 라벨 분산 분해 — 순위 매기기가 어려운 이유

| split | 라벨 std | **그룹 내 분산 비중** | 그룹 간 분산 비중 | 퇴화 그룹 | 그룹 폭 중앙값 |
|---|---:|---:|---:|---:|---:|
| train | 2.980 | **0.341** | 0.659 | 22.7 % | 3.586 m |
| val | 2.495 | **0.407** | 0.593 | 30.9 % | 2.399 m |
| test | 2.584 | **0.418** | 0.582 | 28.3 % | 2.889 m |

**top-1 regret 은 그룹 **안**의 순서만 본다.** 그런데 `loss_max` 분산의
58~66 %는 **그룹 간**에 있다 — 장면이 어렵냐 쉽냐다. 회귀 손실(MSE)은 이
쉬운 부분을 줄이는 데 대부분을 쓰고, regret 을 정하는 34~42 %에는 적게
쓴다. **MSE 로 학습하면서 regret 으로 판정하면 목적이 어긋난다** (추론).
지시서가 "MSE 로 판단하지 않는다"고 한 것이 여기에 정확히 걸린다 —
**판단만 regret 으로 바꿨을 뿐 학습은 여전히 MSE 다.**

이 어긋남을 고치려면 그룹 내 순위 손실(pairwise / listwise)로 바꿔야 하는데,
**지시서에 없는 구조 변경이라 하지 않았다.**

## 12. 예상과 달랐던 것

1. **입력 특성이 라벨 CSV 에 다 없었다.** 계획서 §5.2 가 요구한 서브골이
   빠져 있었고 복원도 불가능해, 플래너를 다시 돌려야 했다 (14.9분).
   재도출이 원본과 5.50e-06 m 오차로 일치한 것은 다행이지만, **라벨 수집이
   토큰을 저장할 때 §5.2 를 대조하지 않았다**는 뜻이다.

2. **`density` 가 `k` 의 상수배였다.** 계획서가 CLS 에 두 개를 요구했는데
   `k/(π·3²)` 이라 정보가 하나뿐이다. 코드를 읽지 않았으면 놓쳤을 것이다.

3. **canonical 후보가 이렇게 강할 줄 몰랐다.** 지시서는 모델/교사/무작위
   3군을 요구했고 무작위가 기준선이었는데, **실제 대안인 canonical 은 무작위보다
   훨씬 좋고 (canonical − 무작위: val −0.454, test −0.643, 둘 다 유의)
   모델과 대등하거나 낫다.**
   무작위만 놓고 봤으면 "모델이 무작위의 2/3 로 줄였다"는 결론이 나왔을 것이고,
   그것은 **실제로 얻는 것이 없는데 얻은 것처럼 보이는 비교**였을 것이다.

4. **best epoch 이 0~3 이다.** 94,949 행이면 충분해 보였는데 유효 표본은
   5,937 장면이었다. 규모 곡선의 25 %·50 %가 epoch 0 에서 멈춘 것도 같은 이유다.

5. **AUC 와 regret 이 데이터에 반대로 반응한다.** 데이터를 4배 늘리면 AUC 는
   0.616→0.717 로 오르는데 regret 은 0.773→0.806 으로 나빠진다. 두 헤드가
   서로 다른 종류의 어려움을 겪고 있다 — 분류는 표본이 모자라고, 회귀는
   그룹 내 신호가 모자라다 (추론).

6. **A2 의 `loss>0` RMSE 가 그 층의 라벨 표준편차보다 크다** (test 2.703 vs
   2.661). 지시서가 기본으로 본 방식인데, 자기가 학습한 영역에서조차 평균
   예측만 못하다.

7. **split 사이 라벨 분포가 꽤 다르다.** `loss>0` 비율이 train 52.6 % /
   val 41.3 % / test 42.7 % 다. uid 단위 분할이라 누수는 없지만 (§10),
   **train 이 다른 분포에서 학습한다.** S5-3E 의 uid 분할은 행 수 비율만
   맞췄고 라벨 분포는 맞추지 않았다.

## 남은 불확실성

- **모델을 붙일 근거가 아직 없다.** canonical 을 이기지 못한다 (§4).
  downstream 통합(플래너 연결)은 이 상태로 정당화되지 않는다.
- **학습 목적이 판정 지표와 어긋나 있다** (§11). 그룹 내 순위 손실로 바꾸는
  것이 가장 직접적인 다음 수인데, 지시서 범위 밖이라 하지 않았다.
- **하이퍼파라미터를 탐색하지 않았다.** d_model 128 / 3층 / lr 3e-4 /
  dropout 0.1 을 원본에서 그대로 가져와 다섯 번 다 같은 설정을 썼다.
  best epoch 이 0~3 인 것을 보면 정칙화나 용량 축소가 도움이 될 수 있으나,
  "게이트 미달 시 코드를 고치지 않는다"에 따라 손대지 않았다.
- **k=4 층의 표본이 작다** (val 32 그룹). 그 층의 AUC 0.504 를 신뢰하기 어렵다.
- **λ=1.0 만 썼다.** 표준화로 두 손실의 크기는 맞췄지만 비율은 조정하지 않았다.
- **S5-3E 가 남긴 `R_interact=3.0 m` 과잉 포착 문제는 그대로다.** 퇴화 그룹
  28~31 %는 그 결과이고, 이 단계에서 표본 조건을 손대지 않았다.
